# 앱 이용 기록과 관리자 이용 현황

## 앱에서 보내는 항목

설정의 **앱 이용 기록 보내기**는 기본 꺼짐이며 선택 사항이다. 서버와 유효한 앱 세션이 있을 때만 전송한다. 수집을 위해 새 게스트를 만들거나 로그인을 자동 재시도하지 않는다. 끄면 대기열을 버리고 새 전송을 중단한다. 이미 서버에 도착한 기록은 보관·정리 정책을 따른다.

- 앱/계정 진입, 네 개 주요 탭 진입·탭을 벗어날 때의 전경 소요 시간.
- 식단 추천·레시피·식단표·저장·장보기·영양 분석·복지·AI·생활 안내·커뮤니티·건강쇼츠의 허용된 API 요청 시작/완료, 성공·실패·취소, 처리 시간.
- 사진 선택, 사진 인식 후보의 명시 선택, 게임 시작·완료, 영상 재생 링크를 누른 횟수.
- 글자 크기·음성 설정 변경과 읽어주기 실행. 값은 미리 정한 크기/켜짐·꺼짐 구분만 보낸다.
- Flutter/플랫폼의 처리되지 않은 앱 오류가 잡히면 고정된 오류 종류만 남긴다. 원문·스택은 보내지 않는다. 프로세스가 종료되기 전 전송을 보장하는 크래시 수집 서비스는 아니다.

질문·답변 원문, 사진, 음식명·분량, 건강/알레르기/소득, 지역·좌표, 레시피/복지/게시글 ID, 이름, 계정 ID, 인증 토큰, 원래 URL·쿼리, 오류 원문은 이벤트에 넣지 않는다. 앱 버전·플랫폼, 결과 수, RAG 결과 종류와 UUID 요청번호는 허용한다. 서버의 엄격한 enum·길이·형식·추가 필드 금지 검증을 거친다.

앱 대기열은 디스크에 저장하지 않고 최대 100개, 한 번에 20개씩 약 10초 단위로 보낸다. 전송은 UI 완료를 기다리게 하지 않는다. 전송 실패한 묶음은 버리며 무한 재시도하지 않는다. 계정/세션 또는 동의 상태 변경 시 이전 대기열을 버리고, 이전 세션에서 시작한 요청의 응답을 새 세션의 기록으로 보내지 않는다. 인증 전·오프라인·강제 종료·수집 거절·전송 실패 때문에 누락될 수 있다.

## API와 저장

- `POST /api/v1/usage-events`: 인증된 앱, consent_version=usage-v1, 최대 20개 이벤트. JSON 본문 최대 32KiB.
- `GET /api/v1/admin/usage-events`: 관리자 전용. days=1~30, feature, outcome, offset, limit. 완료된 요청의 기능별 성공·실패·취소·평균 응답, 날짜별 수집 건수, 최신 이벤트 페이지를 반환한다.
- `POST /api/v1/admin/usage-events/prune`: 관리자 전용. 30일 지난 이용 기록만 삭제한다.

`usage_events`는 사용자 서비스 자료와 별도다. 원래 로그인 세션 ID와 사용자 ID는 저장하지 않는다. 인증 세션에서 만든 도메인 구분 SHA256 값을 중복/전송량 제한에만 사용하고 관리자 응답에서는 제외한다. 이 값은 가명 식별값이며 완전한 익명화를 뜻하지 않는다. 세션별 최근 24시간 4,000개 한도를 트랜잭션 잠금으로 확인한다. 같은 세션·이벤트 UUID의 재전송은 한 번만 저장한다.

수집 시각은 서버가 정한다. 조회 기간·날짜 집계는 한국 시간이다. 기본 7일, 최대 30일 범위이며 요약 통계는 현재 페이지 20건이 아닌 조회 조건 전체를 대상으로 계산한다. 성공률은 성공/완료된 요청 수이며 취소도 완료 요청 분모에 포함한다. 실제 이용자 수·재방문율·영상 시청 시간·추천 이후 끝까지 수행한 비율을 의미하지 않는다. 이벤트는 앱이 보고한 값이며 보안 감사·과금·사용자 평가 근거로 쓰지 않는다.

## 관리자 웹

관리자 로그인 후 **앱 이용 현황**에서 기간·기능·결과를 선택한다. 수집 건수, 완료 요청, 성공·실패·취소와 성공률, 기능별 평균 응답 시간, 날짜별 수집 건수, 최근 이벤트를 확인한다. 실패 필터와 요청번호를 이용해 서버 오류를 추적한다. 수집 거절/기록 없음은 가상의 수치 없이 빈 상태로 안내한다. 새로고침·페이지 이동과 기간 지난 기록 정리를 제공한다. 개인별 행동 추적 화면은 제공하지 않는다.

## 배포·정리·운영 로그

새 API 이미지 배포 시 `alembic upgrade head`를 실행한다. 기존 테이블이나 사용자 기록을 이관하지 않는다. 새로운 앱 버전에서 수집 설정을 켜야 사용 이벤트가 들어온다. 관리자 웹과 API를 모두 갱신해야 새 화면을 쓸 수 있다.

적재 때 만료된 기록을 정리하며 기존 `daily_refresh` 마지막 독립 단계에서도 `prune_usage_events`를 실행한다. 정기 갱신 스케줄이 중단된 경우에도 정리 명령을 실행하거나 관리자 버튼으로 정리할 수 있다. 현재 서버의 정기 실행 설치 여부와 실제 실행 결과는 배포 후 별도로 확인한다.

```bash
python -m app.jobs.prune_usage_events
```

API 운영 로그는 요청번호·허용된 HTTP 메서드·라우트 템플릿·상태 코드·소요 시간만 남긴다. 실제 경로 ID·쿼리·본문·헤더는 넣지 않는다. 배포 이미지의 Uvicorn 기본 access log는 꺼서 원래 URL/쿼리가 다시 기록되지 않도록 한다. 성공한 readiness 반복 호출은 운영 로그에서 제외한다. 개발 PC에서 Uvicorn을 직접 실행할 때도 `--no-access-log`를 사용하면 동일하게 원래 URL 출력을 막을 수 있다. Docker 로그 회전과 사용 이벤트 DB 보관 정책은 별개다.

## 검증

실제 PostgreSQL에서 인증·관리자 권한·세션 폐기, 민감 필드/임의 문자열 차단, 중복·전송량·본문 제한, 필터·페이지와 전체 통계, 보관 기한을 검증한다. Flutter에서는 수집 기본 꺼짐·설정 변경·대기열 상한·계정 전환·동의 철회·실패 비전파·본문/토큰 제외를 검사한다. 관리자 웹에서는 빈 상태·필터·지연 응답 교체 방지·권한 만료·정리 확인·응답 검증을 검사한다. 운영 데이터 수집·실기기 확인 완료 여부는 코드 시험과 구분한다.

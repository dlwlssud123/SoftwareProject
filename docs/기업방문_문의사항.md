## 0. 미팅 개요 및 방문 목적

1. **프로젝트 분석 결과 공유**: 기업 설명서 분석을 바탕으로 수립한 8주간의 핵심 개발 범위 및 아키텍처 개선안 공유
2. **긴급 개발 환경 의사결정**: 팀 내 Mac 장비 부재에 따른 앱 개발 플랫폼(iOS 대여 vs Flutter/React Native/Android) 확정
3. **핵심 기능 우선순위 및 차별화 제안 협의**: 8주 집중 개발 항목(식단·영양·AI) 및 추가 구현 기능(배송 연계, 피드백) 확정
4. **데이터 및 외부 자원 지원 확인**: 기업 보유 데이터, 외부 API(OpenAI/Gemini/YouTube) 키 및 개발 서버 지원 여부 확인

## 1. [긴급/최우선] 앱 개발 플랫폼 및 장비 지원

> **배경:**  
> 기업 설명서 기준 앱은 **Swift / SwiftUI (iOS 17.6 이상, Xcode)** 기반으로 명시되어 있습니다.  
> 현재 저희 팀(앱 개발 담당: 김찬형)은 **팀원 전원이 Windows/Linux 환경이며, Mac 장비를 보유하고 있지 않습니다.**

### Q1-1. iOS 개발용 Mac 장비 대여 가능 여부
- 기존 iOS(SwiftUI) 코드베이스를 그대로 유지·개선하는 것이 필수라면, 기업이나 학교(산학협력단) 차원에서 **개발/빌드용 Mac 기기(맥북 또는 Mac mini 등) 대여가 가능한지** 여쭙고자 합니다.

### Q1-2. 앱 플랫폼 전환(Android 네이티브 또는 크로스 플랫폼) 허용 여부
- 만약 Mac 장비 지원이 어렵거나, 서비스 확장성을 고려할 때 플랫폼 전환이 가능하다면 어느 방향을 권장하시는지 문의드립니다.
  - **옵션 A (크로스 플랫폼: Flutter / React Native)**: 단일 코드베이스로 iOS와 Android를 모두 지원 가능 (추후 Mac 확보 시 iOS 빌드 가능)
  - **옵션 B (Android 네이티브: Kotlin / Jetpack Compose)**: 고령층 스마트폰 사용 비율이 높은 안드로이드 환경에 완벽 최적화
  - **옵션 C (iOS 유지 + 원격/대여 환경 구축)**: 기업 측 요구가 반드시 iOS인 경우

## 2. 프로젝트 개발 범위(Scope) 및 기능 우선순위 (8주 계획)

> **배경:**  
> 과제 수행 기간(총 8주) 동안 5개 탭(식단추천, 영양분석, AI 도우미, 건강쇼츠, 놀이터) 전체를 동일한 비중으로 구현하기보다는, 실질적인 가치를 창출하는 핵심 기능에 집중하고자 합니다.

### Q2-1. 기능별 개발 우선순위(P0 / P1) 검토
- 저희 팀에서는 다음과 같이 우선순위를 설정하여 개발하고자 합니다. 이에 대한 기업의 의견을 여쭙니다.
  - **P0 (핵심 집중 개발 - 1~5주차 집중)**:
    1. **식단추천**: 사용자 건강 조건(질환/알레르기) + 섭취 이력 기반 개인화 메뉴 추천 및 조리 안내
    2. **영양분석**: 식사 사진 촬영/업로드 → 멀티모달 음식 인식 → 공공 영양성분 데이터 매핑 및 계산 → 섭취 기록 확정
    3. **AI 도우미**: 공식 보건·복지 문서 RAG 기반 신뢰할 수 있는 식생활·건강 상담 및 복지 정보 안내
  - **P1 (부가/연계 기능 - 5~7주차 구현)**:
    - **건강쇼츠 / 놀이터**: 영상 풀 조회, 관심사별 추천 및 카테고리 필터링 (기존 로직 안정화 및 UI 개선 중심)

### Q2-2. 신규 차별화 기능(추가 구현) 제안 및 협의
- 수행계획서에 반영된 아래 3가지 추가 기능에 대해 기업 관점에서의 실효성과 피드백을 부탁드립니다.
  1. **개인화 기반(카카오 소셜 로그인 또는 서버 세션 ID)**:  
     단발성 앱이 아닌 고령자의 지속적인 건강 관리를 위해 프로필과 섭취 기록을 누적 관리하는 구조 도입
  2. **식단 추천 → 식재료 배송 서비스 연계**:  
     추천 메뉴 확인 후 필요한 재료 목록을 장보기/배송 서비스(쿠팡, 배민B마트, SSG 등)의 상품/주문 페이지로 연결하는 흐름 구현
  3. **식단 추천 사용자 피드백 루프**:  
     추천받은 메뉴에 대한 맛, 조리 난이도, 선호도 피드백을 수집하고, 이를 관리자 페이지에서 집계하여 다음 추천 알고리즘에 반영

### Q2-3. 최종 산출물의 완료 기준 (Target Definition)
- 8주 차 최종 평가 시 기업에서 기대하시는 완성도 수준이 무엇인지 확인하고자 합니다.
  - **(A) 완성도 높은 시연 시제품(PoC/MVP)**: 주요 사용자 시나리오(5대 탭 통합 흐름) 시연 및 성능/정확도 평가 보고서 중심
  - **(B) 실제 스토어 배포/운영 준비 수준**: 상용 서비스 릴리즈에 준하는 예외 처리 및 배포 파이프라인 구축

## 3. 시스템 아키텍처 및 데이터 저장소 전환 (JSON → DB)

> **배경:**  
> 기존 설명서에는 단일 서버 + JSON 파일 기반 저장소로 구성되어 있습니다.

### Q3-1. PostgreSQL + Vector DB 도입 승인 여부
- 다중 사용자 동시성, 섭취 기록 누적, RAG 기반 문서 검색(임베딩 벡터 검색)의 성능과 안정성을 위해 **JSON 파일 저장소를 PostgreSQL + pgvector(또는 Qdrant) RDBMS 구조로 전면 전환**하고자 합니다.
- 앱 로컬에는 가벼운 캐시/세션 정보만 유지하고, 데이터 처리는 서버 DB에서 통합 관리하는 구조로 변경해도 무방한지 확인 부탁드립니다.

### Q3-2. 기존 소스 코드 수정 허용 범위
- 제공받을 베이스라인 코드의 아키텍처(백엔드 계층 분리, Docker Compose 도입, API 엔드포인트 재설계 등)를 팀의 계획에 맞게 대대적으로 리팩토링하여 개발해도 괜찮은지 여쭙고자 합니다.

### Q3-3. Python 3.12 버전 통일
- 백엔드, 데이터 수집/전처리, AI 모델 연동 파이프라인의 Python 실행 환경을 **Python 3.12**로 통일하여 구성해도 기존 연동에 문제가 없는지 확인드립니다.

## 4. 데이터셋 및 기존 자산 제공 범위

### Q4-1. 기업 보유 데이터셋 제공 가능 여부
- 다음 항목 중 기업에서 이미 확보·구축하여 제공해 주실 수 있는 데이터가 있는지 여쭙고자 합니다.
  - 레시피 및 메뉴 마스터 데이터 (또는 공공데이터 COOKRCP01 활용 권장 여부)
  - 건강/식생활/복지 관련 FAQ 데이터셋
  - 건강쇼츠 / 놀이터용 YouTube 영상 링크 및 카테고리 풀
  - 기존에 검증된 AI 프롬프트 템플릿(System Prompt)

### Q4-2. 건강 상태 분류 기준 확인 (설명서 불일치 정정)
- 기업 설명서 내에 **건강 상태 분류 기준**이 일부 페이지에서는 **12가지**, 다른 곳에서는 **13가지**로 다르게 기재되어 있습니다. 공식적으로 따라야 할 최신 기준(항목 리스트)이 무엇인지 확인 부탁드립니다.

## 5. 외부 API 및 인프라/협업 환경 지원

### Q5-1. 외부 API 키 제공 및 비용 예산/한도
- 서비스 연동에 필수적인 외부 API들의 Key 발급 및 비용 지원 여부를 확인하고자 합니다.
  - **OpenAI API** (멀티모달 비전 `gpt-4o-mini`, 대화 모델)
  - **Google Gemini API** (복지 정보 요약 및 지도)
  - **YouTube Data API v3** (영상 메타데이터 조회)
- 기업에서 발급한 테스트용 API Key 및 사용 한도(월 예산)가 지원되는지, 아니면 팀 자체 크레딧/키를 사용해야 하는지 문의드립니다.

### Q5-2. 테스트 서버(인프라) 지원 여부
- 팀원 간 및 앱-서버 통합 테스트를 위한 클라우드 인스턴스(AWS, GCP 등) 또는 온프레미스 개발 서버 지원이 가능한지, 혹은 팀 자체 로컬/무료 티어로 구축해야 하는지 확인 부탁드립니다.

### Q5-3. 코드 관리 및 멘토링 소통 방식
- **저장소**: 기업 Git 저장소에 접근 권한을 부여받아 작업하는 형태인지, 팀 자체 GitHub에서 진행 후 최종 소스코드를 납품하는 형태인지 확인
- **정기 소통**: 프로젝트 진행 중 기술적 문의나 피드백을 받을 수 있는 소통 채널(Slack, 카카오톡, 이메일 등) 및 정기 멘토링 주기(주 1회 등) 설정 요청

## 선행 결정과 제한

- 11/20 사용자 결정: 사진 인식·AI 도우미 제공자는 **무료 범위 우선**으로 검토한다. 제공자·키·개인정보 처리 조건은 아직 확정하지 않았다. 관리자 웹 로그인은 **전용 아이디·비밀번호** 방식으로 결정했다. 민찬 담당의 기존 `src/admin` 코드를 활용하며, 기존 예시 권한 선택을 실제 인증 완료로 간주하지 않는다.

- 11/18 사용자 확인: 사진 인식·AI 답변의 모델/API 제공자는 아직 미정이다. 11/19까지 제공자·사용량 예산·키 보관 경로를 결정해야 11/21 실제 모델 연동 목표를 유지할 수 있다. 키 값은 문서·로그·Git에 남기지 않는다. 미정 상태에 가짜 분석/답변을 구현 완료로 대체하지 않는다.
- RAG 문서와 조건 임베딩은 같은 KURE 모델·revision·차원·정규화 규약이어야 한다. 다른 외부 임베딩을 쓰려면 문서 전체 재임베딩이 선행된다. API 컨테이너는 768MiB 제한이므로 KURE 모델을 그 안에 상주시킬 계획으로 잡지 않는다. 재영 담당 인덱스의 실행 위치·조회 방법을 먼저 정한다.
- 기업 서버는 별도 신규 DB로 시작했다. 서버 프로세스가 healthy인 것과 레시피·복지·RAG 자료가 적재된 것은 별개다. 사용자 DB 전체를 무단 복사하지 않고 공개 원천 수집본·적재 CLI로 준비한다.
- 매주 레시피/영양 갱신, 매일 복지 갱신 명령·예약 예시는 준비되어 있으나 실제 서버 예약 설치·실행 확인 전에는 자동 적재 완료로 기록하지 않는다.
- #58의 복지 API·본인 메모는 `20261119_01` nullable 컬럼으로 기존 저장을 보존한다. #63에서 앱을 실제 복지 API에 연결했지만 아직 main 병합·기업 서버 재배포 전이다. 현재 배포된 앱·서버와 PR 검증 상태를 혼동하지 않는다.
- 후속 로컬 작업: 급식소·제철·생활 가이드 공개 조회와 관리자 갱신 작업 조회를 추가했다. 새 테이블·실제 콘텐츠·서버 예약은 만들지 않았다. 이전 자동 승인 검토 사용량 한도로 남았던 HTTP·PostgreSQL 통합 검증은 11/19 재실행해 완료했다.
- 11/19 당시 검증: `RUN_DB_TESTS=1` 전체 백엔드 `pytest -q` → **262 passed**, Ruff check·format check 통과. 실제 PostgreSQL의 격리된 시험 스키마에서 게시 필터·판본 변경·권한·저장·메모·기존 적재 회귀를 확인했다. 메모 관련 27개 복지 API 테스트에는 다른 사용자 접근 차단·입력 제한·비우기·철회 자료의 메모 보존·저장 해제 시 제거·마이그레이션 기존 행 보존을 포함한다. 이후 #63 통합 검증은 위 현재 상태에 기록했다. 원천·패키지 검사와 서버 실제 실행·앱 종단 확인은 구분하며, 이 통과 기록은 새 API의 기업 서버 배포 완료를 뜻하지 않는다.
- 서버 초기 적재 중 Python 검증 프로세스의 `STAT=T/do_signal_stop`을 확인해 재개했다. 이후 계산 영양 검증과 실제 API 응답을 확인했다. 11/19 자동 배포 후에도 공개 레시피 1,151건과 `recipe-food-map-v8` 계산 영양이 유지됐다. 임시 HTTPS를 넣은 Release APK는 에뮬레이터에서 게스트 접속·추천·저장을 확인했으며 실제 휴대폰 카카오 인증은 별도 확인한다. APK·비밀 설정은 Git 커밋 대상에 포함하지 않는다.

## 11/20 주제 요청 API 작업

#65 로그인·수집 현황은 실제 PostgreSQL 408개·웹 34개·배포/복귀 CI가, #66 가이드 검수 화면은 웹 47개·린트·빌드 CI가 통과했다. 두 PR은 팀 승인·main 반영·실제 배포 전이다.

현재 `codex/feat-topic-requests`는 #65를 선행으로 주제 접수·본인 목록/상세·취소·관리자 판본 처리/답변·게시 가이드 연결·감사 API를 구현한다. `submission_id` 재시도·취소한 요청의 복원 차단·24시간 접수 한도·행 잠금·원문 없는 감사·계정 삭제 경계를 포함한다. `20261120_05`는 새 테이블만 추가한다. 일반 시험 31개가 통과했고 실제 PostgreSQL 시험 17개는 CI에서 검증한다. 기존 실행 API 계약의 변경이 없음을 대조했다.

이 API 작업을 PR로 공유한 뒤 앱의 임시 주제 메모를 실제 접수·내역·취소로 연결하고 관리자 처리함을 별도 작업으로 연결한다. 요청 생성이 자동 가이드·영상 제작이나 게시를 뜻하지 않는다. 생활 가이드 요청 완료에는 승인·게시한 가이드가 필요하다.

# ValueFlow 관리자 웹

민찬 담당의 React + TypeScript + Vite 관리자 웹 구조에 실제 관리자 로그인·수집 현황을 연결했습니다.
저장소 내 위치는 `src/admin`입니다.

## 현재 구현 범위

- 공통 레이아웃과 관리자 홈
- 수집 상태·콘텐츠 검수·품질 검토 화면 이동
- URL 해시 기반 화면 이동
- 관리자 전용 아이디·비밀번호 로그인과 서버의 `/admin/me` 권한 확인
- 수집 상태·실패 단계 검색·20건 단위 페이지·새로고침·한국 시간 표시
- 401/403·세션 만료 시 이전 화면 제거, 로그아웃·요청 취소·지연 응답 보호
- HTTPS 검증·인증 리다이렉트 차단·요청 제한 시간을 적용한 공통 API 클라이언트
- 로딩·오류·빈 결과·API 연결 대기 표시 컴포넌트

수집 현황은 실제 API를 호출합니다. 콘텐츠 검수·품질 검토 화면은 아직 연결 대기이며, 개발용 권한 선택으로 관리자에 진입하지 않습니다. 가이드 검수·게시 API는 별도 서버 브랜치에 준비되어 있고 웹 연결은 후속입니다. 수집 재시도·예약 실행은 이 화면에서 수행하지 않습니다.

운영자는 서버에서 `python -m app.jobs.provision_admin <아이디>`를 실행하고 프롬프트에서 비밀번호(15~128자)를 입력합니다. 기본 관리자나 공개 회원가입은 없습니다. 앱의 카카오 로그인·일반 사용자 계정과 구분합니다. 관리자 생성·재설정은 서버 운영자가 직접 진행하며 비밀번호를 명령 인자·문서·채팅·VITE 환경변수로 전달하지 않습니다.

웹의 비밀번호·세션은 React 메모리에만 유지하고 localStorage/sessionStorage/쿠키에 저장하지 않습니다. 새로고침·브라우저 재실행 뒤에는 다시 로그인합니다. 기본 재인증 기한은 1시간이며 토큰 갱신으로 이 기한을 늘릴 수 없습니다. 로그아웃은 서버 세션을 폐기하고, 통신 실패에도 브라우저의 내용을 지우되 서버 폐기 여부는 확인하지 못했다고 안내합니다.

## 개발 환경

최초 실행 확인 환경:

- Windows / PowerShell
- Node.js 26.13.0
- npm 11.20.0
- TypeScript 5.9.3

의존성의 실제 설치 버전은 `package-lock.json`으로 관리합니다.
2026-11-20 추가 검증은 Node.js 24.13.0, npm 11.6.2로 실행했습니다. 관리자 CI도 Node 24를 사용합니다. 테스트 도구는 Node 24 호환 버전으로 고정된 잠금 파일을 사용합니다.

## 설치 및 실행

저장소 루트에서 실행합니다.

```powershell
cd src/admin
npm.cmd ci
npm.cmd run dev
```

개발 서버 주소는 터미널에 표시된 주소를 사용합니다.
기본 주소는 `http://localhost:5173`입니다.

종료하려면 개발 서버 터미널에서 `Ctrl + C`를 누릅니다.

## 환경변수

API 연동 시 `.env.example`을 복사합니다.

```powershell
Copy-Item .env.example .env.local
```

- `VITE_API_BASE_URL`: 경로·사용자 정보·쿼리가 없는 서버 origin입니다. 예: `https://api.example.com`. 요청에 `/api/v1`을 붙입니다. 개발 모드에서만 `http://localhost:8000`·`http://127.0.0.1:8000`·IPv6 루프백을 허용합니다. 운영 빌드는 HTTPS만 허용합니다.
- 현재 기본값은 빈칸이며 실제 요청은 수행하지 않습니다.
- 환경변수 변경 후 개발 서버를 다시 실행합니다.
- `VITE_` 변수는 브라우저에 노출되므로 비밀번호·인증키를 넣지 않습니다.
- 실제 환경 파일은 Git에 올리지 않습니다.
- 별도 웹 origin에서 접속하면 백엔드 `CORS_ORIGINS`에 웹 주소를 정확히 등록해야 합니다. 예: `["http://localhost:5173"]`. 쿠키 인증은 사용하지 않습니다.
- 로그인에는 `20261120_04` 이상의 DB·관리자 계정이, 수집 조회에는 `/admin/data-jobs`가 필요합니다. 빌드 성공과 운영 배포·실제 계정 연결은 별도입니다.

## 주요 파일

- `src/App.tsx`: 공통 레이아웃과 화면 이동
- `src/App.css`: 관리자 화면 스타일
- `src/index.css`: 전역 스타일
- `src/api.ts`: `createAdminApi` 팩토리와 로그인·권한·수집·로그아웃 DTO/오류 처리. 기존 `requestJson<T>` 공통 export와 `data/meta` 응답 형식도 유지합니다.
- `src/components/StatusMessage.tsx`: 공통 상태 표시
- `src/components/AccessBoundary.tsx`: 실제 로그인·세션 만료·로그아웃 경계
- `src/components/Collections.tsx`: 실제 수집 현황 화면
- `tests/`: 로그인/권한/필터/지연 응답·API 경계 회귀 시험

## 검증

```powershell
npm.cmd run build
npm.cmd run lint
npm.cmd test
```

수동 확인 항목:

- 관리자 홈과 각 메뉴 사이 이동
- 이동한 화면에서 새로고침 후 화면 유지
- 브라우저 뒤로 가기·앞으로 가기
- 좁은 화면에서 메뉴와 본문 표시
- 로그인 실패·관리자 권한 확인·만료·로그아웃 후 이전 내용 제거
- 수집 필터·한국 시간·빈 결과·오류/재시도

Vitest/JSDOM으로 API/화면 흐름을 검증하며 `.github/workflows/admin-ci.yml`에서 설치·린트·시험·빌드를 실행합니다. 테스트 의존성은 운영 번들에서 사용하지 않습니다. 실제 브라우저의 시각 검사는 격리된 테스트 API로 확인했고, 운영 DB·서버와의 종단 검증을 대신하지 않습니다.

## 서버·데이터 담당자와 확인할 사항

- 이진녕: API 주소·경로·요청/응답·오류 형식
- 이진녕: 로그인 방식·인증 전달·만료 처리·CORS 설정
- 이진녕: 관리자 API의 서버 측 권한 검사
- 최재영: 수집 상태·콘텐츠·품질 필드와 상태값

로그인 발급 후 `/admin/me`로 서버 권한·사용자·만료를 확인합니다. 관리자 요청은 같은 origin에만 Bearer를 보내며 리다이렉트를 따라가지 않습니다. 권한은 각 서버 API에서도 확인합니다. 수집 결과·오류·미완료 화면을 예시 데이터로 대체하지 않습니다. 실제 운영 계정 생성·API 배포·CORS·접속 주소 설정은 운영자가 확인해야 합니다.

## 알려진 확인 사항

기존 잠금 파일의 최초 기록은 moderate 12건이었고, 이번 설치 전후 전체 npm audit는 동일하게 moderate 9건입니다. `npm audit --omit=dev`는 0건입니다. 기존 개발 도구의 취약점은 별도 검토 대상이며 이 기능 변경에서 관련 없는 의존성을 일괄 업그레이드하지 않았습니다.

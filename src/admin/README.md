# ValueFlow 관리자 웹

## 커뮤니티 신고 처리 (2026-11-25)

`커뮤니티 신고` 메뉴에서 미처리 신고를 20건씩 조회하고 원문·신고 이유를 확인한다. 처리 사유를 적고 확인 후 글 숨김 또는 신고 기각을 서버에 반영한다. 글의 expected_post_version을 보내 동시 변경을 감지하며 409에서는 목록을 새로 읽고 다시 선택하도록 한다. 신고자 식별 정보는 표시하지 않는다. API는 기존 `/api/v1/admin/community/reports`를 사용하며 새 DB 마이그레이션은 없다.

`npm test`, `npm run lint`, `npm run build`로 검증한다. 웹 호스팅과 운영 관리자 계정에서의 확인은 별도다.

민찬 담당의 React + TypeScript + Vite 관리자 웹 구조에 실제 관리자 로그인·수집 현황을 연결했습니다.
저장소 내 위치는 `src/admin`입니다.

## 현재 구현 범위

- 공통 레이아웃과 관리자 홈
- 수집 상태·콘텐츠 검수·품질 검토 화면 이동
- URL 해시 기반 화면 이동
- 관리자 전용 아이디·비밀번호 로그인과 서버의 `/admin/me` 권한 확인
- 수집 상태·실패 단계 검색·20건 단위 페이지·새로고침·한국 시간 표시
- 민찬님 PR #74의 요약 카드·작업 목록 디자인을 실제 수집 조회에 적용
- 401/403·세션 만료 시 이전 화면 제거, 로그아웃·요청 취소·지연 응답 보호
- HTTPS 검증·인증 리다이렉트 차단·요청 제한 시간을 적용한 공통 API 클라이언트
- 생활 가이드 목록·제목/검수 상태 검색·페이지 이동, 초안 작성·다중 단계 편집·출처·확인일
- 검수 요청·승인·사유 있는 반려·별도 게시/비공개와 담당자·시각·판본 변경 이력
- 판본 충돌 시 입력 보존과 최신 내용 확인, 저장 결과 불명확 시 중복 전송 차단, 미저장 변경의 새로고침·메뉴 이동 보호
- 생활 안내·영상 주제 요청의 종류/상태/검색·페이지, 답변·승인 후 게시된 가이드 연결·처리 이력
- 로딩·오류·빈 결과·API 연결 대기 표시 컴포넌트

수집 현황·생활 가이드 검수·주제 요청 처리함은 실제 API를 호출합니다. 품질 검토·시설/제철 검수는 아직 연결 대기이며, 개발용 권한 선택으로 관리자에 진입하지 않습니다. 수집 재시도·예약 실행은 이 화면에서 수행하지 않습니다. PR 병합·서버 배포·운영 계정 생성이 끝나야 운영 서버에서 사용할 수 있습니다.

수집 요약은 조회 조건에 맞는 전체 작업 건수와 현재 페이지의 최근 기록 시각·실패·대기/실행 건수를 구분합니다. 원천 데이터 건수나 필수 항목 누락·검토 대기 건수로 추정하지 않습니다. 로딩·실패·인증 만료에는 이전 요약을 표시하지 않습니다. 가상 건수·작업 내역을 운영 화면에 넣지 않습니다.

주제 요청은 **주제 요청 → 요청 선택 → 처리 상태·답변 작성 → 필요한 게시 안내 선택 → 처리 내용 저장** 순서입니다. 완료·보류에는 답변이 필요하고, 생활 안내 완료에는 승인·게시한 가이드가 필요합니다. 영상 완료는 답변 완료이며 자동 제작·게시를 뜻하지 않습니다. 완료와 보류를 서로 바꾸려면 먼저 검토 중으로 저장합니다. 사용자 취소로 404가 확인되면 캐시된 원문·답변도 감추고 목록을 다시 조회합니다. 409·통신 실패 때 입력을 보존하고 최신 조회 전 재전송을 막습니다. 미저장 답변은 상세 닫기·검색·페이지·메뉴 이동·로그아웃·브라우저 종료에서 보호합니다. 처리 이력 조회 실패는 답변을 버리지 않고 따로 재시도할 수 있습니다.

요청 처리함에는 [서버 PR #67](https://github.com/dlwlssud123/SoftwareProject/pull/67)의 `/api/v1/admin/content-topic-requests` 목록·상세·PUT·감사 API와 `20261120_05`까지 적용한 서버가 필요합니다. 웹은 기존 가이드 화면 PR #66을 기반으로 하며 Flutter 요청 화면 PR #68과 같은 계약을 사용합니다. 이 웹 변경에 새 DB 마이그레이션·환경변수·의존성은 없습니다.

생활 가이드는 **초안 저장 → 검수 요청 → 승인 또는 반려 → 별도 게시** 순서입니다. 승인만으로 앱에 노출되지 않습니다. 반려에는 사유가 필요하고, 본문·단계·출처·확인일을 수정해 저장하면 초안·비공개로 돌아갑니다. 기존 자료의 주소는 바꿀 수 없습니다. 다른 관리자의 수정이나 검수로 409가 오면 입력을 유지하고 최신 내용을 불러오기 전까지 재전송을 막습니다. 통신 끊김·시간 초과는 서버 처리 여부가 불명확하므로 자동 재시도하지 않습니다. 새 자료 작성 응답을 못 받은 경우 목록에서 저장 여부를 확인한 뒤 다시 엽니다.

운영자는 서버에서 `python -m app.jobs.provision_admin <아이디>`를 실행하고 프롬프트에서 비밀번호(15~128자)를 입력합니다. 기본 관리자나 공개 회원가입은 없습니다. 앱의 카카오 로그인·일반 사용자 계정과 구분합니다. 관리자 생성·재설정은 서버 운영자가 직접 진행하며 비밀번호를 명령 인자·문서·채팅·VITE 환경변수로 전달하지 않습니다.

웹의 비밀번호·세션은 React 메모리에만 유지하고 localStorage/sessionStorage/쿠키에 저장하지 않습니다. 새로고침·브라우저 재실행 뒤에는 다시 로그인합니다. 기본 재인증 기한은 1시간이며 토큰 갱신으로 이 기한을 늘릴 수 없습니다. 로그아웃은 서버 세션을 폐기하고, 통신 실패에도 브라우저의 내용을 지우되 서버 폐기 여부는 확인하지 못했다고 안내합니다.

## 환경변수

API 연동 시 `.env.example`을 복사합니다.

```powershell
Copy-Item .env.example .env.local
```

- `VITE_API_BASE_URL`: 경로·사용자 정보·쿼리가 없는 서버 origin입니다. 예: `https://api.example.com`. 요청에 `/api/v1`을 붙입니다. 개발 모드에서만 `http://localhost:8000`·`http://127.0.0.1:8000`·IPv6 루프백을 허용합니다. 운영 빌드는 HTTPS만 허용합니다.
- 현재 기본값은 빈칸이며 실제 요청은 수행하지 않습니다.
- 환경변수 변경 후 개발 서버를 다시 실행합니다.
- `VITE_` 변수는 브라우저에 노출되므로 비밀번호·인증키를 넣지 않습니다.
- 실제 환경 파일은 Git에 올리지 않습니다.
- 별도 웹 origin에서 접속하면 백엔드 `CORS_ORIGINS`에 웹 주소를 정확히 등록해야 합니다. 예: `["http://localhost:5173"]`. 쿠키 인증은 사용하지 않습니다.
- 로그인에는 `20261120_04` 이상의 DB·관리자 계정이, 수집 조회에는 `/admin/data-jobs`가 필요합니다. 빌드 성공과 운영 배포·실제 계정 연결은 별도입니다.

- 로그인 실패·관리자 권한 확인·만료·로그아웃 후 이전 내용 제거
- 수집 필터·한국 시간·빈 결과·오류/재시도
- 가이드의 다중 단계 저장·반려 의견·승인/게시 분리·이력·409·전송 실패·미저장 이동 취소
- 주제 요청의 필터·생활 안내 연결·영상 답변·404 원문 숨김·409/응답 유실·이동/로그아웃 시 답변 보존

## 서버·데이터 담당자와 확인할 사항

- 이진녕: API 주소·경로·요청/응답·오류 형식
- 이진녕: 로그인 방식·인증 전달·만료 처리·CORS 설정
- 이진녕: 관리자 API의 서버 측 권한 검사
- 최재영: 수집 상태·콘텐츠·품질 필드와 상태값

로그인 발급 후 `/admin/me`로 서버 권한·사용자·만료를 확인합니다. 관리자 요청은 같은 origin에만 Bearer를 보내며 리다이렉트를 따라가지 않습니다. 권한은 각 서버 API에서도 확인합니다. 수집 결과·오류·미완료 화면을 예시 데이터로 대체하지 않습니다. 실제 운영 계정 생성·API 배포·CORS·접속 주소 설정은 운영자가 확인해야 합니다.

## 알려진 확인 사항

기존 잠금 파일의 최초 기록은 moderate 12건이었고, 이번 설치 전후 전체 npm audit는 동일하게 moderate 9건입니다. `npm audit --omit=dev`는 0건입니다. 기존 개발 도구의 취약점은 별도 검토 대상이며 이 기능 변경에서 관련 없는 의존성을 일괄 업그레이드하지 않았습니다.


## 앱 이용 현황

설정에서 선택적으로 켠 기능 사용·오류·처리 시간 기록을 별도 API로 수집하고, 관리자 웹의 **앱 이용 현황**에서 기간·기능·결과별로 확인한다. 기본 수집은 꺼져 있으며 질문·사진·건강정보 원문은 포함하지 않는다. 자세한 수집 항목·제한·보관·배포 절차는 [앱 이용 기록 안내](../../docs/data/usage_analytics.md)를 따른다.

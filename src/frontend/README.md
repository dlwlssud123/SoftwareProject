# 오늘동행 · ValueFlow Android 앱

큰 글씨·버튼, 음성 안내 원칙을 Flutter로 구현한 발표용 앱이다. 하단 탭은 **식단추천 → 영양분석 → AI 도우미 → 놀이터** 순서이며 첫 화면은 식단추천이다. 놀이터 상단의 **게임하기 / 영상 보기**에서 게임·건강쇼츠·취미 영상을 선택한다. 식단·복지 추천은 각각 **버튼 → 사용자 정보 입력 → 맞춤 결과** 흐름으로 시연한다.

UI는 사용자 제공 화면을 기준으로 흰 배경, 기능명이 표시된 단일 상단 제목, 색·아이콘·문자로 구분하는 큰 버튼으로 구성했다. 식사 시간은 노랑·초록·파랑·주황으로 구분하고, 각 화면에서 긴 소개 문구와 장식 영역을 줄였다.

서버 식단 추천은 `flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8000`으로 Android 에뮬레이터에서 확인할 수 있다. FastAPI 실행 전 DB를 `alembic upgrade head`로 갱신한다. 식사 시간을 정하고 좋아하는 재료, 간단한 조리, 식감, 알레르기, 건강 조건을 필요한 만큼 선택할 수 있다. **다음에도 이 조건 사용하기**로 좋아하는 재료·조리 선호·알레르기를 기기에 기억한다. 앱은 유효한 게스트 토큰을 같은 서버에서 재사용하고, 응답의 추천 이유와 제철 재료를 표시한다. 서버 주소 없이 실행하면 번들 데이터로 발표용 추천이 동작한다. 배포 빌드는 HTTPS 서버 주소를 사용한다.

## 복지 추천·관심 저장·내 메모

서버를 연결하면 **AI 도우미 → 복지 소식 · 맞춤 추천**에서 만 나이·시도·선택 시군구·선택 독거 여부로 실제 복지 API를 조회한다. 이름·소득·건강 정보를 받지 않으며 조건은 검색 요청에만 사용한다. 결과가 없거나 서버에 연결하지 못하면 그 상태를 안내하고 번들 예시로 바꾸지 않는다. 서버 주소가 없는 실행에서는 기존 복지 체험 화면임을 표시한다.

상세에서 지원 대상·선정 기준·지원 내용·신청 방법·문의처와 원천 확인일(한국 시간)을 보여 준다. 정부 도메인의 HTTPS 공식 주소만 외부로 열고, 추천과 관심 저장이 수급 자격 판정이나 실제 신청이 아님을 안내한다. **저장한 복지 · 내 메모**에서 계정별 관심 목록을 20개씩 조회하고 본인 진행 메모(최대 2,000자)를 수정한다. 빈 내용 저장은 메모 삭제이며 관심 저장 해제 전에는 메모도 삭제된다는 확인을 받는다. 현재 안내가 내려간 복지도 기존 메모 확인·삭제 경로는 유지한다.

메모 저장 실패에는 입력을 유지하고 저장 전 뒤로가기에는 폐기 여부를 확인한다. 로그인 만료 뒤 재시도할 때 새 게스트를 만들지 않고 재로그인을 안내한다. 계정이 바뀌는 중 도착한 이전 사용자의 저장·메모 응답을 표시하지 않는다. 일반 설정이나 로그에 메모를 저장하지 않는다.

관련 코드는 `data/welfare_api.dart`, `models/welfare.dart`, `screens/welfare_screens.dart`다. 복지 API·`20261119_01` 마이그레이션·복지 초기 자료 적재가 있는 백엔드가 필요하며, 코드/위젯 검증과 main 병합·기업 서버 데이터 적재·실기기 확인은 별도다. 이 기능은 생성형 복지 RAG 응답이나 자동 신청을 제공하지 않는다.

## 음식 사진과 생활·요리 AI

서버 연결 앱의 영양분석에서 음식 사진을 고른 뒤 **음식 찾고 영양 확인**을 누른다. 첫 이용 시 NVIDIA 외부 처리 안내에 동의해야 전송한다. 음식 이름과 공공 영양 DB의 후보를 확인하고 **반 정도(0.5)·1인분(1)·조금 많이(1.5)**로 분량을 고른다. 원천 1회 분량을 먼저 사용하고 없는 경우 AI의 표준 분량 제안을 사용한다. 모두 사진의 실제 질량을 측정한 값이 아닌 예상 분량으로 표시한다.

다음 화면에서 공공 DB로 계산한 영양을 확인하고 직접 저장해야 식사 기록에 추가된다. 분량은 g/mL로 세부 수정할 수 있고 음식 검색·빼기도 가능하다. 인식 실패나 후보가 없는 음식은 직접 입력하며 예시 영양값으로 대체하지 않는다. 이전 미확인 저장 요청이 있으면 먼저 처리하고 사진 선택은 다시 진행한다. 예상 분량 표시는 로컬 재시도 정보와 저장 상세에도 유지한다.

AI 도우미의 대화 화면은 서버 연결 시 실제 `/ai/chat`을 호출한다. 동의 후 입력한 현재 질문만 보내며 서버 프로필·건강기록·이전 대화는 함께 보내지 않는다. 화면 이탈 시 HTTP를 취소하고 계정이 바뀐 뒤 늦게 도착한 답변은 폐기한다. 서버 미연결 앱은 표시된 사용법 예시만 제공한다. AI 오류를 예시 답변으로 바꾸지 않는다.

음식 사진은 서버와 NVIDIA로 전송되며 우리 서버에는 보관하지 않는다. 얼굴·이름·연락처·주소·진료 정보가 없는 음식 사진만 사용한다. 약 봉투·안내문 사진 AI 풀이는 연결하지 않는다. 키는 서버에만 두며 APK에는 API 주소만 넣는다. 백엔드 `20261124_02`, 공공 식품 데이터 적재, AI 활성화 설정이 필요하다. 실서버 배포·실기기 시험은 소스 검증과 별도다.

## 식단 추천의 제철 근거·쿠팡 검색

서버가 추천에 반영한 제철 재료는 레시피 상세의 **제철 재료와 출처**에 적용 월과 함께 표시한다. **공식 제철 자료 보기**는 정부 HTTPS 출처를 외부로 연다. 이전 서버 응답에 월·출처가 없으면 해당 항목을 표시하지 않고 레시피와 제공된 재료명은 유지한다. 추천 제외 조건과 제철 반영은 기존 서버 규칙을 그대로 따른다.

**쿠팡에서 검색**은 재료명만 전달한다는 확인 뒤 외부로 이동한다. HTTPS·정확한 호스트/포트/검색 경로·재료명과 같은 단일 검색어만 허용하며 사용자 정보·다른 검색어·추가 매개변수·조각 식별자는 거부한다. 이 검사를 기존 장보기와 제철 추천이 함께 사용한다. 가격·재고·배송비는 쿠팡에서 확인하며 이동 취소·브라우저 실패 시 앱 화면을 유지한다. 월별 탐색 화면이나 별도 제철 앱은 이번 변경에 포함하지 않는다.

## 무료급식소·경로식당

서버 연결 앱의 **AI 도우미 → 무료급식소 · 경로식당**에서 시·도와 선택 시·군·구·시설명/주소로 검색하고 20개씩 더 볼 수 있다. 위치 권한 없이 지역 검색이 가능하다. **내 주변 급식소 찾기**를 눌렀을 때만 Android 위치 권한을 요청하며, 반경 1·5·10km 안의 시설을 직선거리 순으로 조회한다. 지역을 함께 선택하면 좌표 없는 같은 시·군·구 시설도 거리 확인 불가로 뒤에 안내한다. 위치 오차를 표시하며 실제 이동 거리나 이용 자격을 판정하지 않는다.

위치는 HTTPS 요청 본문에만 보내며 서버/기기 설정에 저장하지 않는다. 외부 지도에는 시설 주소만 전달한다. 15초 동안 위치를 얻지 못하거나 권한을 거부·취소하면 지역 검색으로 찾을 수 있다. 화면 이탈·탭 전환·백그라운드 전환 시 위치 조회와 HTTP를 취소하고 늦은 응답을 무시한다. 위치/검색 결과는 해당 화면 메모리에서만 유지하며 탭·백그라운드 전환 시 정리한다.

상세는 서버에서 다시 읽고 이용 대상·운영 시간·전화·기준일·주의사항·출처를 표시한다. 일반 전화번호만 전화 앱으로 연결하며 정부 도메인의 HTTPS 출처만 외부로 연다. 비공개·삭제된 정보에는 이전 연락 버튼을 표시하지 않는다. 서버가 없거나 조회가 실패하면 예시 시설로 바꾸지 않는다.

위치 처리는 [geolocator 공식 플러그인](https://pub.dev/packages/geolocator) 14.1.2를 사용하며 Android의 사용 중 위치 권한만 요청한다. 구현에는 `POST /api/v1/meal-facilities/nearby`가 포함된 백엔드와 검수·공개된 시설 자료가 필요하다. 코드/HTTP/위젯 검증, 실기기 권한 동작, 기업 서버 배포·공개 자료 적재는 구분한다.

## 영양분석·섭취 기록

서버·계정이 연결된 앱의 **영양분석 → 먹은 음식 직접 입력**에서 공공 식품 이름을 검색하고 먹은 양을 확인한다. 원천에 중량 근거가 있을 때만 인분을 제공하고, 그 외에는 g·mL와 큰 분량 버튼을 사용한다. 서버의 계산 미리보기에서 결측·일부 계산·g/mL 근사와 원천 기준량을 확인한 뒤 식사 기록을 저장한다. 계량 단위나 영양값을 앱에서 추정하지 않는다. 사진 선택·예시 결과는 별도 체험이며 실제 사진 인식 API 연결을 의미하지 않는다.

**저장한 식사**는 한국 날짜로 조회하며 음식·양·시간 수정과 확인 후 삭제를 제공한다. 상세는 저장 당시 값·확인한 원래 분량·원천 기준량을 보여 준다. 수정/삭제 충돌에는 최신 기록을 확인하도록 안내하고 자동 덮어쓰기를 하지 않는다. 스냅샷 없는 이전 기록은 저장한 수치와 근거 부재를 구분한다.

생성 요청은 전송 전에 `FlutterSecureStorage`의 `pending-intake:<서버 origin>:<사용자 ID>`에 키·섭취 시각·선택한 음식과 양을 임시 보관한다. 일반 설정·로그에 기록하지 않는다. 연속 탭·동시 준비는 같은 요청 키를 사용하며 응답 유실/앱 재시작 후에는 입력을 고정하고 같은 요청으로 재확인한다. 서버 수신이 확인된 뒤 정리하며, 기기 정리 실패로 요청이 남아도 같은 키로 재확인한다. 계정 변경·인증 만료는 새 게스트로 자동 전환해 재전송하지 않는다. 읽을 수 없는 요청은 자동 폐기하지 않으며 저장한 식사를 확인한 사용자의 명시적 선택으로 해당 계정의 임시 요청만 정리할 수 있다. 아직 저장 버튼을 누르지 않은 작성 내용 전체의 복구를 제공하는 기능은 아니다.

관련 코드는 `data/intake_api.dart`, `models/intake.dart`, `screens/intake_screens.dart`이고 API 계약은 [API 명세서](../../docs/설계/API_명세서.md)를 따른다. 실제 기능에는 식품·영양 계산·섭취 기록 API와 초기 식품 데이터가 있는 백엔드가 필요하다. 위젯/HTTP 검증과 main 병합·서버 배포·실기기 종단 확인은 구분한다.

## 실행

장보기는 **하루 식단표 만들기 → 날짜 선택 → 이 날의 장보기 목록**에서 사용한다. 서버 목록을 읽고 구매 체크를 저장하며, 메뉴·분량 변경 충돌 시 새 목록을 읽는다. 140% 큰 글씨·체크 실패/재시도·재진입 후 유지 흐름을 위젯 테스트로 확인한다. 재료명과 원문 분량을 함께 표시하고 인분을 자동 추정하지 않는다. ‘쿠팡에서 재료 찾기’는 허용된 HTTPS 검색 주소를 외부로 열며 레시피 상세의 각 재료에서도 사용할 수 있다. 가격·주문은 외부에서 사용자가 확인한다.

이 화면에는 장보기 API가 있는 백엔드가 필요하다. 코드 구현·위젯 검증과 기업 서버 배포·실기기 확인은 구분하며, 앱이 원격 저장에 성공하기 전에는 체크를 완료로 표시하지 않는다.

Flutter와 Android SDK가 설치된 환경에서 실행한다.

```powershell
cd src/frontend
flutter pub get
flutter run -d emulator-5554
```

Windows의 Flutter 배치 초기화가 지연되면 제공한 실행 스크립트를 사용할 수 있다.

```powershell
# 켜져 있는 에뮬레이터에 실행
./tool/run_android.ps1

# flutter_emulator AVD 창도 함께 실행
./tool/run_android.ps1 -LaunchEmulator

# 발표 시에는 디버그 도구 없이 최적화한 APK를 설치·실행
./tool/run_android.ps1 -Presentation
```

실행 스크립트가 새로 여는 에뮬레이터는 PC의 GPU를 사용한다. 이미 소프트웨어 그래픽으로 실행 중인 에뮬레이터라면 먼저 닫고 `-LaunchEmulator -Presentation`으로 실행한다. 발표 모드의 APK도 현재는 개발용 키로 서명한다.

## API 데이터 갱신

데이터는 **공식 API → JSON 저장 → 앱에 포함** 순서로 가져온다. 현재 식품안전나라 COOKRCP01에서 레시피 50건, 복지로 중앙부처 API에서 목록 461건을 확인한 뒤 어르신 관련 6종의 상세 정보를 수집했다. 추천 시에는 네트워크 없이 고정 규칙을 적용한다.

```powershell
# 키는 저장소 루트의 Git 무시 대상 .env 또는 프로세스 환경변수에서 읽음
# FOODSAFETY_API_KEY / WELFARE_API_KEY (Python 표준 라이브러리만 사용)
python tool/fetch_recipe_data.py --limit 50
python tool/fetch_welfare_data.py

# 갱신한 JSON을 앱에 반영
./tool/run_android.ps1 -Presentation
```

수집 결과는 `assets/data/recipes.json`과 `assets/data/welfare_services.json`, 출처·수집 시각·건수는 `recipe_source.json`과 `welfare_source.json`에 저장한다. 신규 메뉴의 이미지도 다운로드한다. 인증키는 루트 `.env`에만 보관하고 소스·수집 데이터·로그·APK에는 넣지 않는다. `.env`는 Git에서 제외되며 기존 환경변수 값이 우선한다. 식품 키가 없으면 공식 샘플 5건만 수집할 수 있다.

식단은 아침·점심·저녁·간식과 기본·고혈압·당뇨·동시 선택의 16개 조합에 미리 지정한 메뉴 순서를 적용한다. 추가 수집 메뉴는 그 뒤에 정렬하고 알레르기·식감 필터 후 최대 5개를 보여준다. 부드러운 음식 표시는 수작업으로 확인한 2종에만 붙인다.

레시피 상세의 **조리 방법**에서 제공된 모든 단계를 스크롤로 확인할 수 있다. 원문의 단계 번호를 유지하고 중간 번호가 누락된 경우 안내를 표시한다. **한 단계씩 따라 만들기**는 별도로 선택하는 조리 보조 모드다. API 원문에서 빠진 내용을 임의로 채우지 않는다.

**준비할 재료**는 원문의 주재료·소스·양념장 구분을 살려 재료별 행으로 표시한다. 재료명과 분량을 구분하고 큰 글씨에서는 줄바꿈하며, 괄호 안의 설명·분량에 있는 쉼표는 재료 구분자로 사용하지 않는다. 해석할 수 없는 형식은 원문을 그대로 보여준다.

복지는 실제 사업명·설명·지원대상·선정기준·혜택과 개별 복지로 링크를 제공한다. 나이에 맞는 어르신 안내 대상을 고르고 독거·선택 소득 구간에 따라 순서를 조정하지만 지원 자격을 판정하지 않는다. 소득인정액·수급자 여부·중복급여 등 실제 조건은 원문에서 확인한다. 현재 6종은 전국 사업이며 지역별 추가 사업은 포함하지 않는다. 수집 명세는 `docs/관련폴더/활용가이드_중앙부처복지서비스(v2.2).doc`을 따랐다.

## 1분씩 시연하기

1. 식단추천 화면의 **식생활 서비스** 또는 식사 시간별 메뉴 버튼을 누른다.
2. 이름·나이·성별·지역을 입력한다. 빠른 리허설에는 **예시 정보 채우기**를 사용한다. 예시는 가상의 김영희·72세·서울 노원구다.
3. **다음으로**에서 식사 시간·건강 상태·알레르기·식감 조건을 선택하고 정보 이용 안내를 확인한다.
4. **맞춤 레시피 추천받기**로 결과를 확인한다. 시간대와 건강 상태(기본·고혈압·당뇨·두 가지 모두)에 미리 지정한 순서를 적용하며, 알레르기와 부드러운 음식 선택은 실제 필터링한다.
5. **AI 도우미** 탭에서 **복지 소식 · 맞춤 추천**을 누른다.
6. 기본 정보와 가구 형태·소득 구간을 입력하고 **맞춤 복지 서비스 찾기**를 누른다. 실제 전국 사업 목록의 순서가 달라지고 **지원 대상과 혜택 보기**를 펼치면 API 원문을 확인할 수 있다.

두 흐름 모두 상세 화면에 들어가지 않고 추천 결과까지 보여준다. 추천 조건 변경은 결과의 **조건 수정**으로 돌아간다. 개인정보는 메모리에만 보관하며, 설정의 글자 크기와 음성 사용 여부만 기기에 저장한다.

## 구현 범위

서버 주소(`API_BASE_URL`)가 지정되면 식단 탭에서 **하루 식단표 만들기**와 **저장한 레시피**를 이용한다. 레시피 상세와 추천 결과 상세에서 날짜·끼니를 선택해 식단표에 담거나 저장·해제한다. 식단표에서는 날짜별 메뉴 변경·삭제가 가능하고 메뉴를 고를 때 기기에 기억한 알레르기 제외 조건을 적용한다. 추천·식단표·저장은 로그인 화면과 같은 서비스 세션을 사용해 서버 DB에 보관한다. 게시 중단되거나 갱신된 식단 항목은 다시 고를 수 있게 안내한다.

게스트 세션이 만료되기 전에 설정에서 카카오 계정을 연결하면 같은 사용자 ID와 저장 자료를 유지한다. 연결한 사용자는 재로그인해 같은 자료를 조회할 수 있다. 이미 다른 서비스 계정에 연결된 카카오 계정이면 충돌을 안내하며 기존 계정으로 로그인할지 선택한다. 이때 게스트 기록은 자동 병합하지 않는다. 식단표는 메뉴 계획이며 섭취 기록이나 영양 처방을 생성하지 않는다. 장보기 목록 자동 생성과 재료별 쿠팡 검색 연결은 후속 범위다.

| 영역 | 현재 동작 |
| --- | --- |
| 식단 추천 | 식품안전나라 API 레시피 50건에서 시간대·건강 상태별 하드코딩 순서, 알레르기·식감 필터 후 최대 5건, 추천 이유, 상세·단계별 조리·1분 타이머 |
| 복지 추천 | 서버 연결 시 조건별 복지 조회·상세·관심 저장·내 메모. 서버 없이 실행하면 수집된 중앙부처 사업의 체험 화면 |
| 영양 분석 | 카메라·앨범 선택, 사진 미리보기, 공개 레시피의 영양 수치로 예시 결과 체험 |
| AI 도우미 | 복지 추천 진입, 서버의 게시된 생활 안내 목록·전체 단계·읽어주기·주제 요청, 사용법 예시 대화, 사진 보기, 외부 지도 검색 연결 |
| 놀이터 | 같은 그림 찾기, 숫자 순서대로 누르기(1~9), 속담 이어 맞히기(무작위 5문제), 결과·다시 하기, 건강쇼츠·여가 영상 검색, 서버에 영상 주제 요청·답변 확인·취소 |
| 설정 | 글자 100·120·140%, 한국어 기기 TTS, 설정 저장·개인정보 안내 |

식단과 복지의 추천 규칙은 발표용이며 의학적 처방이나 복지 수급 자격 판정이 아니다. 사진을 고르는 것만으로 영양 분석 결과를 생성하지 않으며, 예시 결과는 별도 버튼으로 구분한다. 예시 대화도 실제 생성형 AI 연결과 구분해 표시한다. 외부 링크를 제외한 핵심 추천 흐름은 오프라인에서 동작한다.

## 실제 서버 연동에 필요한 키

생활 안내는 **AI 도우미 → 생활 도우미**, 영상 주제 요청은 **놀이터 → 영상 보기 → 보고 싶은 주제 요청 · 내역**에서 연다. 요청은 한 줄 60자까지이며 운영자에게 전달한다. 내역·답변·연결된 게시 안내를 볼 수 있고 요청 취소 시 원문·답변을 지운다. 전송 전 서버·계정별 보안 저장소에 전송 번호와 본문을 보관한다. 통신 실패 후 다시 열어도 기존 번호로 접수를 확인하며 같은 내용 재전송 또는 취소를 선택한다. 계정 변경 시 이전 입력·내역은 즉시 감춘다. 서버 주소가 없으면 접수를 성공으로 표시하지 않고 요청 버튼을 비활성화한다. 새 경로는 `20261120_06`까지 적용한 백엔드가 필요하며, 이 변경만으로 운영 서버·기존 APK가 갱신되지는 않는다.

번들 데이터 체험에는 키가 필요 없다. 수집 스크립트는 루트 `.env`의 식품·복지 인증키를 사용한다. 서버의 실제 AI 기능에는 아래 공급자 설정이 필요하다. 키는 **Python 서버의 환경변수**로 관리하고 APK·Dart 소스·Git에 넣지 않는다.

| 용도 | 필요한 인증 정보 | 비고 |
| --- | --- | --- |
| 레시피 수집 | 식품안전나라 OpenAPI 인증키 | FOODSAFETY_API_KEY. 인증 성공·50건 수집 확인 |
| 중앙부처 복지 서비스 수집 | 공공데이터포털 중앙부처복지서비스 활용신청·인증키 | WELFARE_API_KEY. 인증 성공·6종 상세 수집 확인 |
| 실제 지역 복지 서비스 | 공공데이터포털 지자체복지서비스 활용신청·인증키 | 중앙부처 서비스와 별도 활용신청 확인 |
| 생활·요리 대화·음식 사진 | NVIDIA Build/NIM API 키 | NVIDIA_API_KEY와 NVIDIA_AI_ENABLED. 시험 사용 조건 확인 후 서버에서 활성화 |
| 자동 영상 수집 | YouTube Data API v3 키 | 외부 YouTube 검색 링크에는 필요 없음 |
| PDF 방식의 검색·지도 AI | Gemini 등 선택한 검색 공급자 키 | 현재 외부 지도 검색 링크에는 필요 없음 |

공공 원천 API의 인증 정보는 Python 수집 작업에서 사용하고, 서버 주소가 있는 Flutter 앱은 FastAPI의 식단·복지·기록 API를 호출한다. 서버 주소가 없을 때는 번들 JSON으로 체험한다. 공공 레시피 API는 데이터 원천이며 개인화 추천 알고리즘 자체를 제공하는 것은 아니다. 복지 API도 대상 정보를 제공하므로 실제 자격은 공식 기준으로 확인해야 한다.

## 카카오 로그인 실행

기존 설정에서 쓰던 `.env.local`은 Git에서 제외되는 JSON 형식의 Dart define 파일이다. `API_BASE_URL`과 `KAKAO_NATIVE_APP_KEY`를 설정한다. Android 패키지 `com.valueflow.valueflow`와 서명 키 해시를 카카오 개발자 앱에 등록해야 한다.

```powershell
flutter run --dart-define-from-file=.env.local
```

휴대폰 시연용 release APK는 응답이 정상인 HTTPS 주소를 설정한 뒤 빌드한다.

```powershell
flutter build apk --release --dart-define-from-file=.env.local
```

Flutter 3.44.4에서는 테스트용 플러그인 등록 파일이 남은 상태로 `--no-pub`를 붙이면 `integration_test` Java 클래스를 찾지 못하는 release 빌드 오류를 재현했다. 기본 pub 단계를 포함해 release용 등록 파일을 생성한다. 생성 Java 파일을 직접 편집하거나 테스트 의존성을 삭제하지 않는다. [Flutter 관련 수정 논의](https://github.com/flutter/flutter/pull/194204)를 참고한다.

게스트로 시작한 뒤 설정의 **카카오 로그인**에서 계정을 연결한다. 기존 `mealGuest:<서버 origin>` 토큰은 새 계정 저장소로 이전하며 추천·식단표·저장 레시피가 같은 계정을 사용한다. 토큰 만료 시 재로그인을 안내하고, 로그아웃·다른 사용자 로그인 때 이전 화면의 개인 데이터는 재사용하지 않는다.

## 사진 인식 후 유사 음식 선택

사진에서 인식한 이름을 영양 DB에서 찾지 못하면 서버가 반환한 유사 음식의 기준량·성분을 참고값으로 보여준다. 유사 후보는 자동 선택하지 않으며, 사용자가 음식과 분량을 확인한 뒤 실제 DB 영양값으로 계산한다. 이름이 비슷해도 재료·조리법에 따라 영양은 달라질 수 있다는 안내를 표시한다. 후보가 없으면 인식한 이름을 채운 수동 검색 화면으로 이동하거나, 음식 이름을 AI로 보내 일반적인 1인분 재료를 예상할 수 있다. 사진은 다시 보내지 않는다.

예상 재료 화면에서 DB 식품 연결·양 변경·재료 제외를 확인한 뒤 원래 음식 확인 화면으로 돌아온다. 미연결 재료가 체크돼 있으면 진행할 수 없으며, 제외하는 경우 누락된 영양이 합계에 포함되지 않는다는 확인 문구를 표시한다. 확인한 재료는 다른 음식과 함께 기존 식사 기록 화면에서 합산하고 저장한다. 물만 있거나 선택한 재료가 없으면 계산하지 않으며, 한 번에 음식·재료 합계 30개까지 담을 수 있다.

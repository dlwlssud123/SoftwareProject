# 오늘동행 · ValueFlow Android 앱

기업 서비스 설명서의 하단 5개 탭, 큰 글씨·버튼, 음성 안내 원칙을 Flutter로 구현한 발표용 앱이다. 식단·복지 추천은 각각 **버튼 → 사용자 정보 입력 → 맞춤 결과** 흐름으로 시연한다.

UI는 사용자 제공 화면을 기준으로 흰 배경, 기능명이 표시된 단일 상단 제목, 색·아이콘·문자로 구분하는 큰 버튼으로 구성했다. 식사 시간은 노랑·초록·파랑·주황으로 구분하고, 각 화면에서 긴 소개 문구와 장식 영역을 줄였다.

## 실행

Flutter와 Android SDK가 설치된 환경에서 실행한다.

```powershell
cd src/frontend
flutter pub get
flutter run -d emulator-5554
```

Windows의 Flutter 배치 초기화가 지연되면 제공한 실행 스크립트를 사용할 수 있다.

```powershell
# 켜져 있는 에뮬레이터에 실행
./tool/run_android.ps1

# flutter_emulator AVD 창도 함께 실행
./tool/run_android.ps1 -LaunchEmulator

# 발표 시에는 디버그 도구 없이 최적화한 APK를 설치·실행
./tool/run_android.ps1 -Presentation
```

실행 스크립트가 새로 여는 에뮬레이터는 PC의 GPU를 사용한다. 이미 소프트웨어 그래픽으로 실행 중인 에뮬레이터라면 먼저 닫고 `-LaunchEmulator -Presentation`으로 실행한다. 발표 모드의 APK도 현재는 개발용 키로 서명한다.

## API 데이터 갱신

데이터는 **공식 API → JSON 저장 → 앱에 포함** 순서로 가져온다. 현재 식품안전나라 COOKRCP01에서 레시피 50건, 복지로 중앙부처 API에서 목록 461건을 확인한 뒤 어르신 관련 6종의 상세 정보를 수집했다. 추천 시에는 네트워크 없이 고정 규칙을 적용한다.

```powershell
# 키는 저장소 루트의 Git 무시 대상 .env 또는 프로세스 환경변수에서 읽음
# FOODSAFETY_API_KEY / WELFARE_API_KEY (Python 표준 라이브러리만 사용)
python tool/fetch_recipe_data.py --limit 50
python tool/fetch_welfare_data.py

# 갱신한 JSON을 앱에 반영
./tool/run_android.ps1 -Presentation
```

수집 결과는 `assets/data/recipes.json`과 `assets/data/welfare_services.json`, 출처·수집 시각·건수는 `recipe_source.json`과 `welfare_source.json`에 저장한다. 신규 메뉴의 이미지도 다운로드한다. 인증키는 루트 `.env`에만 보관하고 소스·수집 데이터·로그·APK에는 넣지 않는다. `.env`는 Git에서 제외되며 기존 환경변수 값이 우선한다. 식품 키가 없으면 공식 샘플 5건만 수집할 수 있다.

식단은 아침·점심·저녁·간식과 기본·고혈압·당뇨·동시 선택의 16개 조합에 미리 지정한 메뉴 순서를 적용한다. 추가 수집 메뉴는 그 뒤에 정렬하고 알레르기·식감 필터 후 최대 5개를 보여준다. 부드러운 음식 표시는 수작업으로 확인한 2종에만 붙인다.

레시피 상세의 **조리 방법**에서 제공된 모든 단계를 스크롤로 확인할 수 있다. 원문의 단계 번호를 유지하고 중간 번호가 누락된 경우 안내를 표시한다. **한 단계씩 따라 만들기**는 별도로 선택하는 조리 보조 모드다. API 원문에서 빠진 내용을 임의로 채우지 않는다.

**준비할 재료**는 원문의 주재료·소스·양념장 구분을 살려 재료별 행으로 표시한다. 재료명과 분량을 구분하고 큰 글씨에서는 줄바꿈하며, 괄호 안의 설명·분량에 있는 쉼표는 재료 구분자로 사용하지 않는다. 해석할 수 없는 형식은 원문을 그대로 보여준다.

복지는 실제 사업명·설명·지원대상·선정기준·혜택과 개별 복지로 링크를 제공한다. 나이에 맞는 어르신 안내 대상을 고르고 독거·선택 소득 구간에 따라 순서를 조정하지만 지원 자격을 판정하지 않는다. 소득인정액·수급자 여부·중복급여 등 실제 조건은 원문에서 확인한다. 현재 6종은 전국 사업이며 지역별 추가 사업은 포함하지 않는다. 수집 명세는 `docs/관련폴더/활용가이드_중앙부처복지서비스(v2.2).doc`을 따랐다.

## 1분씩 시연하기

1. 식단추천 화면의 **식생활 서비스** 또는 식사 시간별 메뉴 버튼을 누른다.
2. 이름·나이·성별·지역을 입력한다. 빠른 리허설에는 **예시 정보 채우기**를 사용한다. 예시는 가상의 김영희·72세·서울 노원구다.
3. **다음으로**에서 식사 시간·건강 상태·알레르기·식감 조건을 선택하고 정보 이용 안내를 확인한다.
4. **맞춤 레시피 추천받기**로 결과를 확인한다. 시간대와 건강 상태(기본·고혈압·당뇨·두 가지 모두)에 미리 지정한 순서를 적용하며, 알레르기와 부드러운 음식 선택은 실제 필터링한다.
5. 뒤로 두 번 돌아가 **복지 추천**을 누른다. AI 도우미 탭의 **복지 소식 · 맞춤 추천**에서도 같은 흐름으로 들어갈 수 있다.
6. 기본 정보와 가구 형태·소득 구간을 입력하고 **맞춤 복지 서비스 찾기**를 누른다. 실제 전국 사업 목록의 순서가 달라지고 **지원 대상과 혜택 보기**를 펼치면 API 원문을 확인할 수 있다.

두 흐름 모두 상세 화면에 들어가지 않고 추천 결과까지 보여준다. 추천 조건 변경은 결과의 **조건 수정**으로 돌아간다. 개인정보는 메모리에만 보관하며, 설정의 글자 크기와 음성 사용 여부만 기기에 저장한다.

## 구현 범위

| 영역 | 현재 동작 |
| --- | --- |
| 식단 추천 | 식품안전나라 API 레시피 50건에서 시간대·건강 상태별 하드코딩 순서, 알레르기·식감 필터 후 최대 5건, 추천 이유, 상세·단계별 조리·1분 타이머 |
| 복지 추천 | 실제 중앙부처 사업 6종, 나이·독거·소득 구간에 따른 안내 순서, 지원대상·선정기준·혜택, 개별 복지로 상세 연결 |
| 영양 분석 | 카메라·앨범 선택, 사진 미리보기, 공개 레시피의 영양 수치로 예시 결과 체험 |
| AI 도우미 | 복지 추천 진입, 사용법 예시 대화, 답변 읽어주기, 사진 보기, 외부 지도 검색 연결 |
| 건강쇼츠 | 주제 선택, YouTube 검색 연결 |
| 놀이터 | 여가 주제 선택, 영상 검색 연결, 앱 내부 같은 그림 찾기 게임, 현재 화면에서 주제 메모 |
| 설정 | 글자 100·120·140%, 한국어 기기 TTS, 설정 저장·개인정보 안내 |

식단과 복지의 추천 규칙은 발표용이며 의학적 처방이나 복지 수급 자격 판정이 아니다. 사진을 고르는 것만으로 영양 분석 결과를 생성하지 않으며, 예시 결과는 별도 버튼으로 구분한다. 예시 대화도 실제 생성형 AI 연결과 구분해 표시한다. 외부 링크를 제외한 핵심 추천 흐름은 오프라인에서 동작한다.

## 실제 서버 연동에 필요한 키

앱 실행과 발표 시연에는 키가 필요 없다. 수집 스크립트는 루트 `.env`의 식품·복지 인증키를 사용한다. 향후 실시간 서버·AI 연동도 아래 키를 **Python 서버의 환경변수**로 관리하고 APK·Dart 소스·Git에 넣지 않는다.

| 용도 | 필요한 인증 정보 | 비고 |
| --- | --- | --- |
| 레시피 수집 | 식품안전나라 OpenAPI 인증키 | FOODSAFETY_API_KEY. 인증 성공·50건 수집 확인 |
| 중앙부처 복지 서비스 수집 | 공공데이터포털 중앙부처복지서비스 활용신청·인증키 | WELFARE_API_KEY. 인증 성공·6종 상세 수집 확인 |
| 실제 지역 복지 서비스 | 공공데이터포털 지자체복지서비스 활용신청·인증키 | 중앙부처 서비스와 별도 활용신청 확인 |
| 자유 대화·사진 분석 | 선택한 AI 공급자 API 키 | 구현계획의 OpenAI 등. 모델은 서버에서 선택 |
| 자동 영상 수집 | YouTube Data API v3 키 | 외부 YouTube 검색 링크에는 필요 없음 |
| PDF 방식의 검색·지도 AI | Gemini 등 선택한 검색 공급자 키 | 현재 외부 지도 검색 링크에는 필요 없음 |

현재 외부 API 호출은 Python 수집 스크립트에서 수행하고, Flutter 앱은 저장한 JSON을 읽는다. 상시 실행하는 Python 서버는 아직 포함하지 않는다. 공공 레시피 API는 데이터 원천이며 개인화 추천 알고리즘 자체를 제공하는 것은 아니다. 복지 API도 대상 정보를 제공하므로 실제 자격 검증 기준을 별도로 검토해야 한다.

## 검증 명령

```powershell
flutter analyze
flutter test
flutter drive --driver=test_driver/integration_test.dart --target=integration_test/app_test.dart -d emulator-5554
flutter build apk --debug
```

Android 통합 테스트는 두 시연 흐름과 모든 탭·큰 글자 화면을 확인하고 `build/screenshots/`에 실제 앱 화면을 저장한다. 디버그 APK는 `build/app/outputs/flutter-apk/app-debug.apk`, 발표 모드 APK는 같은 폴더의 `app-release.apk`에 생성된다. 현재 서명은 발표·개발용이며 스토어 배포용이 아니다.
